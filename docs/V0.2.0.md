# Version 0.2.0 — RPG progression and respawn

The existing Phaser renderer, shared deterministic simulation, two-seat room manager and SaveStore boundary remain in place. This release adds permanent characters without accounts or changing the transport framework.

## Try it at localhost:8080

```sh
docker compose up -d --build --wait
# Or with Node 24:
npm ci
npm run dev
```

Open http://localhost:8080 and choose Panda or Ape. Solo and co-op use the same combat, progression, forge and respawn rules. For co-op, create a room and join its code from a second browser context with the other hero.

1. **Respawn:** follow the trail northeast from camp and defeat a slime (Space or left click). Leave its original spawnpoint by at least 160 pixels. Slimes respawn after 20 simulation seconds; wolves after 30 seconds and wisps after 40. Staying close delays a spawn until the spot is safe. Solo pause freezes timers; an occupied online room keeps running while inventory is open. Idle empty rooms freeze. Spawn coordinates remain fixed and each slot has one generation. The original slime spawn inside an obstacle has been moved from (1120,800) to (1080,760), including legacy migration.
2. **Attributes:** defeat three normal enemies for the first level. Press **I** and use the `+ vitality`, `+ strength`, `+ dexterity` or `+ magic` buttons. Every earned level grants exactly three points. The menu shows remaining points and resulting HP, mana, damage, special damage and armor. Spending is immediate and persisted. Attack more enemies to see the resulting combat changes.
3. **Forge:** walk over drops for coins, leather, crystals and ancient materials. Wolves supply leather. The first upgrade costs **20 coins, 2 leather and 1 crystal**. Return to **Bramble**, west of Rowan at camp (390,990); press **E** or **I**, then **Upgrade weapon**. The next price, current weapon level and damage are shown. Panda has an Oakguard sword; Ape a Moonbloom staff. Upgrades +0 through +10 increase actual melee/projectile and special damage. Ancient materials become required at +6. Upgrade rejection appears inside the menu.
4. **Guardian:** the boss never respawns automatically. After victory, collect its ancient drop, bring both heroes out of the encounter area and return to Rowan. Open **I** and select **Reset guardian encounter at Rowan**. The authority verifies camp proximity, boss defeat, no uncollected ancient loot and a 400-pixel safe distance from the arena for everyone. The reset clears outstanding effects/projectiles and starts a new boss generation. Forest quest rewards remain claimed.
5. **Persistence:** use Escape → **Save progress**, reload and continue/reconnect. Solo progress is saved per hero in the browser; starting a new solo adventure keeps the hero's progression but starts a fresh region. In co-op, character credentials stay in browser localStorage, room reconnect data in sessionStorage. A valid 0.1 session credential is also adopted for its migrated permanent character. After a seat expires (60 seconds), create or join a new room with the same hero and browser to continue its permanent character. Attempting to use that character while it still occupies a room or reserved seat is rejected. An invite contains only the room code.

XP is shared by both room heroes, including a temporarily disconnected reserved hero. Drops are shared world objects: the first hero to collect a drop receives its contents, exactly once. Inventory uses identified material stacks, so quantities are consolidated rather than creating ambiguous duplicate stacks. Solo progress is deliberately separate from online characters; uploading editable browser saves into authoritative online characters is not supported.

## Configuration and balance

`packages/shared/src/rpg.ts` owns `RESPAWN`, weapon definitions, XP, attributes and upgrade costs. Default populations are four slimes, three wolves, three wisps and one guardian, bounded by their fixed spawn slots. Spawn checks include terrain collision, other live enemies and all hero positions, including reserved disconnected heroes.

The server accepts an optional `RESPAWN_CONFIG` JSON environment variable. Each supplied enemy entry must include `seconds` (0–3600), integer `maximum` (0–10) and `safeDistance` (0–1000). Omitted types keep defaults. Guardian `seconds` must remain 0 and `maximum` 1. A maximum of 0 disables that type's future spawns. Settings apply to new rooms; existing persisted rooms keep their recorded rules. Invalid configuration stops startup. For Docker, set the variable in the server service's environment via a local Compose override; `.env` alone is not implicitly forwarded. Solo defaults come from the shared definitions.

```sh
# A quicker development-only slime timer:
RESPAWN_CONFIG='{"slime":{"seconds":5,"maximum":4,"safeDistance":160}}' npm run dev
```

XP needed for the next level is `75 × level + 25 × (level − 1)²`, with surplus carried across multiple levels. Vitality adds 12 HP and armor per point. Strength increases sword damage, special damage and armor. Dexterity improves attack cooldown, movement and both weapon damages. Magic increases staff/special damage, maximum mana and regeneration. Level-ups retain the prior 20 HP increase and refill HP/mana. All formulas execute in `shared` on the authority.

Upgrade `n` costs `20n²` coins, `2n` leather, `n` crystals and, from +6, `n−5` ancient materials. Each sword upgrade adds 4 damage; each staff upgrade adds 5. Boss kills always drop ancient material; ordinary kills use a deterministic authority-side 12% roll. Drop outcomes and quantities never come from network messages.

## SQLite migration, durability and recovery

The production server uses Node 24's built-in `node:sqlite`; no downloaded native adapter is needed. `SqliteSaveStore` implements `SaveStore`. The database is `SAVE_DIR/saves.sqlite` (Docker: `/app/data/saves.sqlite`, in the existing `saves` volume). Schema version is held in `PRAGMA user_version`; future incompatible versions stop startup instead of being overwritten.

Tables separate permanent `characters`, uniquely identified `inventory` stacks and unique `rewards` receipts from temporary `rooms`. `migrations` records imported JSON filenames. Inventory, character progress, receipts and the corresponding room snapshot commit together in a serialized `BEGIN IMMEDIATE` transaction. SQLite WAL with `synchronous=FULL` supplies atomic committed replacement and crash recovery. Save requests capture state when queued; later simulation ticks cannot change an earlier queued snapshot. RPG command sequence numbers reject replays. Enemy reward receipts combine room instance, fixed spawn ID and generation; loot has its own receipt. A dead enemy cannot award twice, and generations increase only on a validated respawn/reset.

Rewards, pickups, quest state, successful RPG actions, joins and disconnects trigger saves; normal autosaves still run every 15 seconds, and shutdown flushes the queue. Recent room recovery remains limited to 60 seconds; permanent characters are independent of that window. Character credentials are SHA-256 indexed, never returned in invitations or logged; room snapshots necessarily retain reconnect secrets and backups must remain private.

On startup, every valid 0.1 JSON file named `CODE.json` is validated and imported **once**, including expired rooms' permanent characters. Old room positions, HP, quest state and session expiry remain eligible only under the original recent-room policy. Levels and XP are retained, existing crystals become identified stacks and migrated heroes receive three unspent points per previously earned level. Each source JSON is copied into `backups/` before its import transaction; originals remain untouched. Corrupt files are ignored and retained. No saves volume is deleted.

Existing SQLite stores receive a consistent `VACUUM INTO` backup on startup, followed by atomic rename from `.tmp` to a timestamped `.sqlite` in `backups/`. Backups are retained without automatic pruning. For an extra consistent live backup:

```sh
docker compose exec server node --input-type=module -e 'import { SqliteSaveStore } from "./apps/server/dist/sqlite.js"; const s = new SqliteSaveStore("/app/data"); await s.loadAll(); await s.backup(); await s.close();'
```

For recovery, stop the project's server, first copy the complete data directory to a separate backup, then replace `saves.sqlite` with the selected completed `.sqlite` backup and remove the old WAL/SHM sidecars before restarting. A room's 60-second reconnect window is not extended by restoring a backup. Permanent characters remain available through their browser credential. Never restore an old database over a running server or delete the Docker volume. Original JSON imports can be reprocessed only into a fresh database; already recorded imports cannot overwrite newer progression.

Browser solo snapshots remain browser-local, now in a `{version:2, world}` envelope with separate per-hero character records. The former versionless snapshot is validated and migrated when **Continue saved solo adventure** is chosen; its first original is preserved as `panda-save-v1-backup`. Missing/corrupt snapshots retain their original backup and allow a new adventure. They are not implicitly uploaded to the server's SQLite database.

## Verification

Unit tests exercise progression, real combat effects, atomic costs through +10, inventory uniqueness, safe fixed respawns, cap enforcement, shared rewards, boss reset and legacy migration. SQLite tests exercise simultaneous saves, character recovery outside a room, JSON imports, backups, inventory identities and receipt uniqueness. Real WebSocket clients verify shared stat/weapon/XP/loot/respawn state and rejection of malformed, replayed and unaffordable actions. Chromium covers solo migration, point allocation, forge upgrades and persistence alongside existing gameplay/reconnect/revive scenarios. The production restart script compares progression, equipment, inventory, receipts and enemy generations as well as the original room identity, movement and HP checks.
